\section{Garbled Circuits}
\label{sec:garbledcircuit}
A \acrlong{gc} can be informally defined as a two-party protocol, in which both parties want to evaluate a shared function $C$ together, without revealing their inputs to each other. The two parties participating in the protocol are called the \cgarbler (or the \acrlong{gc} generator), and the \cevaluator. The function $C$ needs to be expressed as a boolean circuit if a \acrlong{gc} protocol is used. Input hiding is achieved using something called \textit{\textbf{garbling}}, which in practice is some form of encryption. Similarly, the final output is initially garbled, and needs to be ungarbled, which is then implemented using a corresponding decryption function. 

\input{figs/gc_protocol.tex}

A simple run of the protocol starts with both parties possessing their own input bit respectively ($g$, and $e$). The protocol proceeds as follows (ref. Figure \ref{fig:garbledcircuitprotocol}):
\begin{enumerate}
    \item The \cgarbler garbles the circuit $C$ to obtain the \acrlong{gc} $C'$, along with some encoding information ($enc$) and decoding information ($dec$). These will be used to garbled and ungarble inputs and outputs.
    \item The \cgarbler garbles its own input $g$ into $g'$.
    \item The \cgarbler then sends across $C'$, $g$ and $dec$ to the \cevaluator.
    \item The \cevaluator still needs to garble its own input, but does not possess the encoding information, $enc$ to do so. Therefore, both parties participate in what is called a 1-out-of-2 \acrfull{ot} protocol \cite{C:EveGolLem82}. This protocol (adapted for \acrshort{gc}s) requires the \cgarbler to garbled both possible bit-values that the \cevaluator may possess, and provide them to the OT protocol. Then, the \cevaluator provides their chosen bit $e$ to the OT protocol and the OT protocol returns the garbling of that bit ($e'$). The \cgarbler remains unaware of which garbling was sent to the \cevaluator, and the \cevaluator remains unaware of the value of the other garbling.
    \item At this point, since the \cevaluator possesses both garbled inputs ($g'$ and $e'$) and the \acrlong{gc} ($C'$), it can compute the garbled output, $y'$ by running the garbled inputs through the \acrlong{gc}.  
    \item Finally, using the decoding information $dec$, the \cevaluator can obtain $y$ by ungarbling $y'$. This output is equivalent to the output of the function $C(g,e)$.
    \item If necessary, the \cevaluator can send the final output back to the \cgarbler.
\end{enumerate}
The protocol can also be scaled up to support larger inputs from both parties. However, this would increase the complexity of the \acrlong{ot} protocol.

Both the \cgarbler and \cevaluator are assumed to be \textit{honest-but-curious}.  
This means that both parties adhere strictly to the protocol specification. However, they try to learn more than what is intended by using the information received from running the protocol, and from their own randomness and state. So, as an example, the \cevaluator could try to obtain the \cgarbler's bit by ungarbling it, but will not suceed since the algorithm $dec$ that the \cevaluator receives does not ungarble the inputs.

This kind of adversary is equivalent to the `Semi-Honest' adversary described by Aumann and Lindell in \cite{JC:AumLin10}.

\section{Garbling Schemes}
\label{sec:garblingschemes}

In the previous section, we discussed a \acrshort{2pc} \acrlong{gc} protocol. However, it is easier to reason about a part of the security of such a protocol using a more generalized construct called a \acrlong{gs}. A \acrlong{gs} leaves out the \acrlong{ot} sub-protocol and focuses on the correctness and security properties of the garbling of the circuit and the input.

A \acrlong{gs} \cite{bellare_foundations_2012} can be expressed as a 5-tuple of algorithms 
\[\mathsf{(Garble(Gb), Encode(En), Decode(De), Garbled Eval (Ev), Eval(ev))}\]

\begin{enumerate}
    \item $\mathsf{Garble(Gb)}$ takes as input the function $f$ and the security parameter $\secparam$ and returns $(F, e, d)$, where $F$ is the \acrlong{gc}, $e$ is the encoding information and $d$ is the decoding information. 
    \item $\mathsf{Encode(En)}$ takes as input the initial input $x$ and the encoding information $e$, and returns the garbled input $X$.
    \item $\mathsf{Garbled Eval (Ev)}$ takes as input the \acrlong{gc} $F$ and the garbled input $X$, and returns a garbled output $Y$.  
    \item $\mathsf{Decode(De)}$ takes input the garbled output $Y$ and the decoding information $d$, and returns the ungarbled output $y$.
    \item $\mathsf{Eval(ev)}$ takes as input the function $f$ and the plain input $x$ and returns $f(x)$. We will just substitute this with $f(x)$.
\end{enumerate}

Relating this to the represenatation of the \acrlong{gc} protocol in the previous section, the inputs $g$ and $e$ from the previous section are both shares of $x$. That is, $x$ can be expressed as $x=g \concat e$. 

\subsection{Properties}
\label{subsec: garblingschemeprops}
The correctness property of a \acrlong{gs} describes its intended behavior. It says that if $(F,e,d) \sample \mathsf{Gb}(\secparam,f),$
\[\forall x, \mathsf{De}(\mathsf{Ev}(F,\mathsf{En}(x,e)),d) = f(x)\]
Besides correctness, a \acrlong{gs} can have one or more of the following security properties \cite{bellare_foundations_2012}:
\begin{enumerate}
    \item \textbf{Privacy}: Knowledge of $(F,X,d)$ does not reveal anything beyond $f(x)$. This means that it is impossible for an \cevaluator to obtain the initial input of the \cgarbler.
    \item \textbf{Obliviousness}: Knowledge of $(F,X)$ does not reveal anything. This means that despite being able to solve the \acrlong{gc}, the solver would not be able to map the garbled output to the real output without $d$.
    \item \textbf{Authenticity}: Knowledge of $(F, X)$ does not allow one to find a $Y'\neq \mathsf{Ev}(F,X)$ such that a $d$ exists to solve ($De(d, Y') \neq \bot$). 
\end{enumerate}

Of these properties, \textbf{Privacy} is the one that is most important to us in this work, and it is what we will continue working with in the rest of the paper.



\subsection{Defining Privacy}
\label{sec:defininigprivacy}
%talk about a simulator based definition of privacy and a IND based one.
In \cite{bellare_foundations_2012}, Bellare, Hoang and Rogaway define privacy as two different cryptographic games: an \textit{indistinguishability} based one (Game\ $\mathsf{PrvInd_\mathit{G,\Phi}}$), and a \textit{simulation} based one (Game\ $\mathsf{PrvSim_\mathit{G,\Phi,S}}$) as described in Figure \ref{fig:prv}.
In these notations, and elsewhere, $\mathit{\Phi}$ refers to the side information function, which describes how much information about the circuit is public. In common usage, it is often either the whole circuit (denoted as $\mathit{\Phi_{circ}(C))}$, the topology of the circuit ($\mathit{\Phi_{topo}(C)}$), or the size of the circuit ($\mathit{\Phi_{size}(C)}$). 

\input{figs/GamePrvInd.tex}

In the indistinguishability based game (Game\ $\mathsf{PrvInd^b_\mathit{G,\Phi}}$), the $\mathsf{GARBLE}$ oracle takes as parameters two pairs of functions and corresponding inputs, $(f_0,x_0)$ and $(f_1,x_1)$ such that $f_0(x_0)=f_1(x_1)$, and the bit $b$ that defines which $(f,x)$ pair $\mathsf{GARBLE}$ will use. A distinguishing adversary $\ddv$ tries to guess the bit-value $b$ that was used to generate the $(F,e,d)$ tuple. 
A $\mathsf{INITIALIZE}$ procedure samples the value of $b$ and it is unknown to the adversary. $\mathsf{GARBLE}$ then uses the selected $(f,x)$ to generate $F$, $X$ and $d$ and returns it to the adversary.
The advantage of the distinguishing adversary here is defined as the difference in the probability that the adversary guesses the correct bit and the probability of guessing randomly ($P=1/2$). \\
If $b'$ is $\ddv$'s guess, 
\[ \advantage{}{D, G^0_{\mathsf{PrvInd}}, G^1_{\mathsf{PrvInd}}} = \lvert \prob{b'=b} - \frac{1}{2} \rvert\]

\textcolor{red}{rewrite next 2 paras for clarity}\\
However, most follow-up works such as Half-Gates \cite{EC:ZahRosEva15} and Free XOR \cite{ALP:KolSch08,JC:Applebaum16}, use the simulation based paradigm (the PrvSim game from Figure \ref{fig:prv}).
Since privacy here means that the running the garbling and encoding algorithms $Gb$ and $En$ does not reveal anything about $f$ or $x$, we let the simulator $\sdv$ access everything that someone participating in the protocol (semi-honest party) would be able to see, i.e., the security parameter (\secparam), the output of the algorithm $y$, and the information function of the circuit $\Phi(f)$. Then, this simulator tries to generate a $(\bar{F},\bar{X},\bar{d})$ tuple whose distribution is computationally indistinguishable from the one generated by actually running $Gb$ and $En$. 

If the distribution of $(\bar{F},\bar{X},\bar{d})$ is actually indistinguishable to an adversary $\adv$ from $(F,X,d)$, an adversary cannot claim to have recovered anything more than what the simulator knew, and hence the privacy of $f$ (except $\Phi(f)$) and $x$ is preserved. For further reading on simulators, Lindell provides a comprehensive overview of simulators for beginners in \cite{lindell_how_2017} . 

\subsection{Yao's Garbling Scheme}
\label{subsec:yaosgarblingscheme}
Before we get into the optimizations for \acrlong{gs}, we must first define a base. In this work, we consider the garbling scheme model defined in \cite{JC:LinPin09}, and will refer to it as Yao's \acrlong{gs}. The garbling of a circuit $f$ consists of $n$ garbled gates, where $n$ is the number of gates that compose the original circuit before garbling. Each (garbled and ungarbled) gate has two input wires ($A$ and $B$) and one output wire ($C$). Each of these ungarbled wires can have two possible values on each wire - 0 or 1 (corresponding to real-life boolean circuits). We will use $a$, $b$, and $c$ to refer to the actual bit-values of each wire. Figure \ref{fig:garbling-and-gate} shows this as a diagram, and the truth table of an AND gate.

\input{figs/garblingagate.tex}

Now, we map each of the possible values on each wire to a random string of length $\secpar$ denoted by the wire name and the bit-value it was mapped to. This random value is called the wire label for that particular wire and bit-value combination. For example, the random value mapped to the 0-input on wire $A$ would be called $A_{0}$. After repeating this process to get all six wire labels ($A_0,A_1,B_0,B_1,C_0,C_1$), we can generate the garbled table. It is worth noting that this mapping from the wire's bit-value to the wire label corresponds to the encoding information $e$ used in the $\mathsf{En}$ function in the description of a \acrlong{gs} in Section \ref{sec:garblingschemes}. 

The garbled table contains 4 rows, like the truth table, and it contains encryptions of the wire label of the output value of each row ($C_{a\land b}$), under two keys - the wire labels of the corresponding inputs ($A_a$,$B_b$) that generated the output $a\land b$ in that row of the truth table. For example, if we consider row 1 of Figure \ref{fig:garbling-and-gate}(c), we would have 
\[X_1 = \enc(A_0, \enc(B_0, C_0)).\]

We know from the protocol description in Section \ref{sec:garbledcircuit}, that besides the garbling of the circuit, the \cgarbler also sends the "garbling" of the inputs to the \cevaluator. These garblings of the input refers to the wire labels corresponding only to the inputs that the parties want to evaluate using the circuit. Thus, the \cevaluator receives the garbled table, as well as the wire labels of the inputs (which, for a single wire, can either be 0 or 1, but not both simultaneously). We observe from Figure \ref{fig:garbled-and-gate} that decrypting any row requires possession of a specific $A$ wire label and a specific $B$ wire label. This means that if the \cevaluator only recieves only one $A$ label and only one $B$ label, they cannot decrypt any row other than the one that was encrypted using those labels since atleast one of the two decryptions will fail. This preserves the privacy of the original bit-value of wire $C$. However, this requires that the \cgarbler provides a mapping from the final output wire labels to the real bit-value of that wire. This would correspond to the decoding information $d$ used in the function $\mathsf{De}$. 

In this \acrlong{gs}, we assume that when trying to decrypt a ciphertext without the right keys, the decryption will fail and the decryptor will know that it has failed. This can be achieved by concatenating some specific, publicly-known padding in the wire labels for wire $C$. This is related to a property called special correctness that where attempting to decrypt a ciphertext without a valid key will result in a decryption failure message with overwhelming probability. This character $\bot$ is commonly used to show such a result in cryptographic notation. Special correctness is a property used later in our work as well.
\input{figs/garbledtable.tex}

For a larger circuit, garbled tables are generated for each garbled gate in the original circuit, and all of them are transmitted to the \cevaluator. In addition to this, a larger circuit would have a larger input as well, so the wire labels correspoding to every input bit is also sent.

\section{Optimizations to Yao's Garbling Scheme}
\label{sec:garblingoptimizations}
\newacronym{pnp}{P\&P}{Point and Permute}
\newacronym{grr}{GRR}{Garbled Row Reduction}
\newacronym{freexor}{FreeXOR}{Free XOR}
\newacronym{hg}{HG}{Half Gates}
In the last two decades, there have been many optimizations that improve the efficiency of Yao's \acrlong{gs}, in terms of the computational costs of garbling, evaluating, and also in terms of the bandwidth consumption when transmitting the \acrlong{gc}. In this section, we discuss the optimizations that are relevant to our work, namely - \acrfull{pnp}\cite{STOC:BeaMicRog90}, \acrfull{grr}\cite{ACMCEC:NaPiSu99}, \acrlong{freexor}, and \acrlong{hg}. 
\subsection{Point and Permute}
\label{subsec:pointandpermute}
On observing Yao's \acrlong{gs}, it quickly becomes obvious that the \cevaluator may have to decrypt 4 rows of the garbled table in order to receive the correct output wire label. Yao's \acrlong{gs} also requires special correctness, which is not difficult to implement, but there is a way to avoid the whole problem in the first place. This technique, now called \acrlong{pnp}, is based on the value $\lambda_{W-1}$ defined in the protocol in \cite{STOC:BeaMicRog90}. 

To put simply, for each wire $W$ in the circuit, with wire labels $W_0$ and $W_1$, each of length $\secpar$, an extra bit is sampled (called the permute or color bit). Let us call this bit $l_W$. Then, for each wire W,
\[W_0 = W_0 \| (l_W) \text{, and}\]
\[W_1 = W_1 \| (l_W\xor1)\]
Now, when generating a garbled table, the ciphertexts are ordered based on the permute bit of the wire labels used to encrypt it. For example, if we say that the encryption generated by wire labels $A_a$ and $B_b$ would be in row $2l_a+l_b+1$, and if $A_0$ and $B_0$ both have the permute bit $1$, the garbled table would be ordered as in Figure \ref{fig:pnp-garbling}.
\input{figs/pnpgarbling.tex}
Then, the \cevaluator can see the last bits (the permute bits) of both input wire labels and identify which row to decrypt in order to obtain the output wire label. This process continues until the end of the circuit is processed since each output wire label contains a permute bit as well, and all the garbled tables are ordered based these permute bits. However, this requires that the \cevaluator and \cgarbler use the same method of permuting the rows, which can be defined in the protocol specification. 

This method reduces the number of ciphertexts to be decrypted by the \cevaluator to 1, which makes the evaluation faster.
\subsection{Garbled Row Reduction-3}
\label{subsec:grr3}
\acrlong{grr}, also known as \acrlong{grr}-3 refers to a scheme first introduced by Naor et al. in \cite{ACMCEC:NaPiSu99}, Section 2.5 under the heading `Optimizing the circuit size'. It allows the number of rows in the garbled table of a boolean gate with two inputs to be reduced to \textit{three} instead of \textit{four}, thus reducing the bandwidth overhead by $25\%$. The 3 in the name of the scheme refers to the three rows in the table.

This technique works by setting one row of the garbled table of each gate to 0, and therefore assuming it implicitly, instead of sending it. Let us say that row $X_{a,b}$ of the garbled table of a gate is the one being ommitted. Here, $a$ and $b$ are the bit-values of the input wires $A$ and $B$ for that gate.
Since we would normally compute that row as 
\[X_{a,b} = \enc(A_a, \enc(B_b, C_c))\]
\[ \text{and since} X_{a,b} = 0^\secpar\] 
It would mean that the \cevaluator could compute 
\[C_c = \enc^{-1}(B_b, \enc^{-1}(A_a, 0))\]

Initially, it might seem that this is insecure since the wire label $C_c$ depends on $A_a$ and $B_b$ instead of being randomly sampled, it is not actually he case as the \cevaluator cannot see the value for $C_c$ unless it has $A_a$ and $B_b$, and if it has those two wire labels, it cannot have the wire labels needed to view the $C_{C\xor1}$ present in the other rows of the garbled table.

This technique can also be combined with the \acrfull{pnp} optimization, where the deleted row would correspond to the permute bits $(0,0)$. However, in this work, we do not deal with the \acrlong{pnp} optimization to reduce the complexity of the proof, especially in Domino.

\subsection{Free XOR}
\label{subsec:freexor}
\newacronym{ccr}{CCR}{Circular Correlation Robust}
\newacronym{lin}{LIN}{Linear}
\newacronym{rk}{RK}{Related-Key}
\newacronym{kdm}{KDM}{Key-Dependent-Message}
\newacronym{linrkkdm}{LIN-RK-KDM}{Linear, Related-Key, Key-Dependent-Message}

The Free XOR optimization was a big step in the optimization of \acrlong{gc}s, allowing the transmission of a XOR gate for free, i.e., without the need to generate, send, or evaluate a garbled table for an XOR gate. This is a big improvement when we consider that circuits can be optimized to maximize the number of XOR gates. It was introduced by Kolesnikov and Schnieder in \cite{ALP:KolSch08}.
\input{figs/freexortable.tex}
Instead of sampling each of the wire labels for every wire independently, the Free XOR scheme samples a global offset $\Delta$ such that for each wire $W$, \[W_1 = W_0\xor\Delta\text{, where $W_0 \sample\bin^\secpar$}\]
Then, for each XOR gate with input wires $A$,$B$ and output wire $C$, the \cevaluator can compute the value of the active wire label of $C$ as $C = A\xor B$ (see Figure \ref{fig:freexortable}).
Since this calculation of the active wire label of $C$ is always true for XOR gates, the \cgarbler can just indicate the presence of a XOR gate, omitting the cost of encrypting the output wire labels. These garblings also do not reveal the wire bit-values they correspond to, so privacy remains intact.

Kolesnikov and Schnieder also note that NOT gates can be implemented in a garbled circuit for free by simply flipping the bit value of the wire they serve as input to.  

Kolesnikov and Schnieder proved the security of the Free XOR scheme under the Random Oracle Model \cite{CCS:BelRog93}, and we see a different notation for the encryption scheme used in \cite{ALP:KolSch08}. Given a Random Oracle $H: \bin^{\*} \mapsto \bin^{\secpar +1}$, and a gate at index $i$ with operation $op\in\{AND,OR,...\}$,
\[X_{a,b} = H(A_a \concat B_b \concat i)\xor C_c\]
This scheme was later proved secure under a stronger \acrfull{ccr} hash assumption in \cite{TCC:CKKZ12}.

However, Free XOR was also proved secure by Applebaum in \cite{JC:Applebaum16} under a different assumption called `\acrlong{linrkkdm}' (\acrshort{linrkkdm}) security for encryption schemes, which uses the same encryption definition as Yao. This is the scheme that we use to prove the security of the FreeXOR scheme in this paper.
